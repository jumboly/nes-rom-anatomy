## 決定事項

1 はユーザー確認済み、2 以降は相談せずおすすめで進めたもの。見直したいものがあれば番号で指定してください。

1. **戻る・進むはブラウザ履歴にした（確認済み）。** 移動ごとに `history.pushState` で URL hash を積む。ROM は URL に入らないので、ROM を開くごとにセッション ID を振り、別 ROM・リロード前の履歴項目に戻っても何もしない。ROM を開いた時点で hash は消す。
2. **履歴項目には「移動先」だけでなく全ビューの位置を持たせた。** 当初は移動先だけを積んだが、逆アセンブルで飛び先をたどった後に初期状態へ戻ると、逆アセンブル表示だけ元に戻らない（Phase 5 のカード内「戻る」より後退する）ことに気付いたため。戻ると、表示が変わっていたビューだけを描き直し、スクロール位置も復元する。これに伴い、**Phase 5 の逆アセンブルカード内の「← 戻る」ボタンは削除した**（ブラウザの戻ると二重になり、どちらで戻るか迷うため）。カードの説明文に「ブラウザの戻るで戻れる」と書いた。
3. **履歴に積むのはリンク・ボタン・Go だけ。** Hex の byte のクリック、Pattern Table のタイルのクリック、CHR の bank 切り替えは今の履歴項目への上書き（`replaceState`）にした。細かい選択のたびに積むと、戻るを何度も押さないとビューを越えられないため。逆アセンブルの「続きの 64 命令」は記録しない（戻ると先頭の 64 命令になる）。
4. **hash の書式は `#hex=8010-801F` / `#cpu=FFFA` / `#disasm=C000` / `#chr=01029` / `#tile=01020`。** 数値はすべて 16 進。アドレスバーで書き換えても移動できる（書式が崩れていれば無視）。`#chr` は Hex から来た「1 byte」でその byte と行を強調し、`#tile` はタイルを選んだだけの状態。
5. **Hex の説明欄を「他の視点での位置」の一覧にした。** PRG なら CPU アドレス（ミラーは全部）と逆アセンブル、CHR なら「bank / pattern table / Tile / 何行目・どちらの plane」、Trainer なら `$7000-`。UxROM などは CPU アドレスを「bank 切り替え次第」としたまま、固定 bank（推定の場合は「推定の末尾 bank」）に入る byte だけ逆アセンブルへのリンクを出す。
6. **移動元が指していた byte 範囲を Hex で薄く塗る。** 命令（1〜3 byte）、タイル（16 byte）、ベクタ（2 byte）。選んだ 1 byte は従来の黄色、範囲はその薄い色。CPU では連続でもファイル上で飛ぶ場合（NROM-128 の `$BFFF`→`$C000`）は先頭 1 byte だけにした（間の無関係な byte まで塗らないため）。
7. **operand の番地は absolute 系（`abs` / `abs,X` / `abs,Y` / `(ind)`）だけ CPU アドレス表示へのリンクにした。** ゼロページ系は常に内蔵 RAM なので対象外。分岐・JMP・JSR は従来どおり逆アセンブルへ。`STA $2000` のようなレジスタも CPU 表示で「PPU レジスタ」と説明が出る。
8. **逆アセンブル表の CPU 列は、PRG が固定の Mapper でだけ CPU 表示へのリンクにした。** CPU アドレス表示は bank 切り替えのある Mapper の固定 bank に未対応（Phase 7 で扱う）で、リンクしても「未対応」が出るだけのため。CPU / File 列は全行がリンクになるので、下線と色は hover 時だけにした。
9. **Tile Inspector の plane 0 / plane 1 の各 byte を Hex へのリンクにした。** 同じ行の 2 byte がファイル上で 8 byte 離れていることを確かめられるようにするため。
10. **スクロール位置はスクロールが止まって 200 ms 後に記録する。** スクロールのたびに `replaceState` すると Safari の呼び出し回数制限に当たるため。記録が履歴の移動と競合しないよう、履歴項目に通し番号を振り、表示中の項目にだけ書く。
11. **UI の E2E テストはリポジトリに入れていない。** Python 版 Playwright のスクリプトで手元確認した。テストの仕組み（npm 依存の追加・CI）は #14 で決めるため。

## 設計上の判断

- **逆向きの対応は既存の関数の組み合わせで作った。** Hex → CPU は `prgToCpu`、Hex → 逆アセンブルは `disasmMapping` + `prgToCpu`、Hex → タイルは `locateTile` の逆。独自に対応を計算すると、Trainer・ミラー・固定 bank の扱いが各ビューと食い違うため。`tileAtChrOffset` は `locateTile` との往復で、xref は Synthetic 4 種と UxROM / MMC1 / 64 KiB NROM で検証した。
- **ビューは Navigator に `show`（場所を表示）と `current`（今の場所）を登録するだけ。** ビュー同士は互いを知らないので、作る順番や循環参照を気にせずリンクを足せる。表示できないビュー（CHR-RAM の Tile Inspector、PRG の無い ROM の逆アセンブル）は登録しないので、そこへのリンクも出ない。
- **逆アセンブルに使う対応の選択を `disasm.ts` に移した。** Hex の「逆アセンブル」リンクと逆アセンブル表示が同じ範囲を対象にしないと、リンク先で「読めない」と出るため。

## ブラウザでの確認

Chromium（幅 1200px ライト / 390px ダーク）で以下 27 項目を確認し、すべて期待どおり・コンソールエラーなし。

| ROM | 確認内容 |
| --- | --- |
| Synthetic NROM-256 | Hex `$0010` → 説明欄に `CPU: $8000` / `逆アセンブル: $8000` / `RESET の飛び先` → 逆アセンブル → `JMP $800D` をたどる → 戻る ×2 で逆アセンブルも `$8000` に戻る → 進む ×2 |
| 同上 | operand `$2000` → CPU 表示に「PPU レジスタ」、Vectors の飛び先 → CPU 表示 → 「ここから逆アセンブル」→ 戻る ×2 で離れた時点のスクロール位置に戻る |
| 同上 | Hex で CHR の byte（File `$9039`）→ 「Tile $02 の 1 行目・plane 1」→ Tile Inspector で `+9` の byte と行がハイライト → File offset → Hex で 16 byte が範囲表示（`#hex=9030-903F`） |
| 同上 | アドレスバーで `#disasm=8100` に書き換えて移動、不正な hash は無視 |
| Synthetic NROM-128 | ROM を切り替えると hash が消え、前の ROM の履歴項目に戻っても何も起きない。`CPU: $8100 / $C100` の両方のリンク、CPU 表示のミラー側リンク |
| UxROM 128 KiB（自作） | 固定 bank の byte は「bank 切り替え次第（固定 bank では `$C001`）」+ 逆アセンブルのリンク、切り替え bank の byte には逆アセンブルのリンクなし、逆アセンブルの CPU 列はリンクなし |
| nrom-template256 / nestest | 表示、飛び先・Hex への移動、戻る（コンソールエラーなし） |
